Muon 如何对应高斯参数，以及正确性验证

每条链的参数记为 p = [x, y, log σx, log σy, θ, a]，按 s = [0.15, 0.15, 0.025, 0.025, 0.025, 1] 组成 q = p/s；因此梯度乘 s，更新也乘 s。这与原 Adam 每类参数的基础步长一致。没有直接混合像素、弧度和亮度单位。

N×6 版本将整条链放进一个矩阵；分组版本把 [x,y]、[log σx,log σy] 放进两个 N×2，角度和亮度由 Adam 更新。两种方案都从同一个目标加权随机初始化开始，没有 MCMC。Muon 使用 momentum=0.95、Nesterov、5 次 Newton–Schulz、系数 (3.4445,−4.7750,2.0315)、原始 sqrt(max(1,N/K)) 缩放、零 weight decay；随后做相同的参数投影。

这是对高斯参数的实验性移植。Muon 原实现面向神经网络隐藏权重矩阵，不能把其优势直接推广到此问题。Newton–Schulz 在这里近似正交化动量，不是在解拟合损失的 Hessian，也不等于 GN / LM。

本次全部使用 FP32。原实现的 BF16 正交化改为 FP32，不声称与 BF16 逐位一致或使用了 Tensor Core。N×6 只需 6×6 Gram，更新在单个 CUDA block 的共享内存完成；此处没有测半精度收益。

这一版“凸”在哪里

局部模型为 Hⱼ = JⱼᵀJⱼ，解 (Hⱼ + λDⱼ)Δⱼ = −Jⱼᵀr；Dⱼ为有正下界的对角缩放。每个阻尼二次子问题是凸的，联合高斯拟合仍非凸。

实现保留6σ ROI和解析Jacobian，使用FP32 Cholesky；求解后限步并投影到参数边界。每条链同时试更新全部高斯，重新渲染；只有6σ近似渲染下的连续全图MSE下降才接受，否则增大阻尼。

这是一种分块、LM式阻尼方法，省略了不同高斯之间的JᵀJ交叉项；不等于精确求解全局LM子问题，也没有测试独立的幅度凸优化。

验证结果

  • 32个实际GPU局部系统，与独立Float64全图中心差分比较：梯度最大相对L2误差 6.99e-07，Hessian 1.76e-07，更新步最大绝对差 1.48e-05。
  • 全部19次运行（含1次预热）的参数交回原版renderer / loss：MSE一致、0个不同像素。
  • 程序检查每一步、每条链的LM连续损失均不增加；外部脚本再检查导出的曲线和接受/拒绝计数。
  • 优化连续未取整、未截断的强度误差，最终验收仍是原版round / clip MSE；两者不能混同。

为什么没有赢：目前的判断

单步需要累计6维梯度和21个Hessian元素，并额外渲染候选、验收和提交。局部曲率没有换来足够多的迭代节省。

重叠高斯之间的耦合被分块近似省略，是后续值得验证的原因。它目前是解释假设，不是已完成的归因消融。矩阵自由的全局Jv / Jᵀv求解可能改善这一点，但本次没有性能结论。

02 / THE CORE ALGORITHM

它是 2D 加法高斯拟合。

没有 3D 相机、深度排序或 alpha 合成。每颗高斯只有位置、两个尺度、角度和幅度这六个参数。

保留下来的计算定义

gⱼ(p) = αⱼ exp[−½(u²/sₓ² + v²/sᵧ²)]
I(p) = clip(round(Σⱼ gⱼ(p)), 0, 255)

u、v 为旋转到高斯局部坐标后的像素位置。损失 L 是 I 与目标的全图 MSE；取整和截断在求和以后进行，不能先截断 S 再做增量更新。

真正要消掉的浪费

S′(p) = S(p) − gₒₗd(p) + gₙₑw(p)

原版每次只改一个参数，却重算所有像素上的所有高斯，重复三角函数并 JSON 深拷贝整个数组。缓存总和与单颗贡献，候选只算一颗：每步从 O(PN) 降至 O(P)，贡献缓存占 O(PN) 内存。

01 / PROPOSE

选择高斯与参数

均匀扰动并保留原 clamp。位置步长 2，尺度 1，角度 0.1，幅度 10。

02 / EVALUATE

只求新增贡献

sin/cos 每颗预计算；复用候选缓冲，仍评价全部像素，不截断尾部。

03 / ACCEPT

按原规则接受

min(1, exp(−ΔL/T))。损失是取整后图像的 MSE，SSE 用整数累加。

04 / COMMIT

接受后更新缓存

CPU 交换数组；GPU 在 block 内统一决策、同步提交，再开始下一步。

边界说明：clamp 提案在参数边界通常不对称，原代码没有 Hastings 修正，因此这里把它视为随机优化器，不保证严格分布采样。增量式是实数代数等价；浮点累积在半整数取整边界可能改变轨迹，一致性结论只覆盖已测用例。

04 / GPU DESIGN & UTILIZATION

让状态和迭代留在显存里。

本报告试跑已改为WebGPU ROI + Adam。此节保留最初常驻MCMC内核设计与desk profiler数据。

已实现的并行布局

GPU grid: 32 independent chains
  each block: 256 threads
    thread 0    → proposal + acceptance decision
    all threads → pixels + integer SSE reduction
    barrier     → commit before next proposal

Parameters / contributions / sum / RNG stay on GPU.
Host launches 256-step chunks; no per-step readback.

一条链仍严格顺序执行。不能从同一旧状态提出多个重叠候选后全部接受。工作区约 C × P × (N+2) × dtype 字节，启动限制不超过当时空闲显存的一半。

MFU：统计口径与实测状态

最终渲染 + Adam 梯度两内核采样的 FP32 指令算术利用率约 14.97%。不是模型训练定义的 MFU，也不是整个程序平均。

  • renderSparse：SM throughput 73.23%，occupancy 83.97%。
  • refineAdam：SM throughput 66.33%，occupancy 83.07%。
  • 算术利用率使用实际 FADD + FMUL + 2×FFMA，按两内核时间和实测 SM 时钟加权；不含整数 / SFU / FP64，也不含 memset、MCMC、CPU、传输和空隙。

先前全图 MCMC 样本为3.85%，SM throughput 9.48%、occupancy 24.98%。新优化器增加跨高斯并行度。两组是不同阶段的内核样本，不能当作同一工作量的整体MFU对比。原始数据见 ncu_final.csv。

nvidia-smi 的 GPU Util 是采样期内的忙碌比例，不是峰值 FLOPS 利用率，还包含其他进程。这个内核含 exp、除法、整数 SSE、同步，不能用“原始全量重算 FLOPs”作优化后的 MFU 分子；省掉的计算不算已执行 FLOPs。

ROI MCMC → 稀疏渲染 → 并行 Adam。FP16 模式在局部 exp / 幅度乘法使用半精度；缓存模式另外复用 ROI 指数值，参数、梯度和 Adam 状态保留 FP32，最后 1,000 步用 FP32 收尾。累加采用 1/1024 灰度的 u32 定点，避免浮点原子加法依赖。最终 MSE 由后台 Float64 全图、无截断重渲染计算。

总耗时从点击运行开始，包含首次管线编译、初始化、GPU 计算、回传和 Float64 验证；重复运行复用管线并单独标记。GPU 时间来自 timestamp-query。运行期间可停止；没有 WebGPU 时会明确提示。通过 localhost 打开兼容性更好。
