02 / THE CORE ALGORITHM

它是 2D 加法高斯拟合。

没有 3D 相机、深度排序或 alpha 合成。每颗高斯只有位置、两个尺度、角度和幅度这六个参数。

保留下来的计算定义

gⱼ(p) = αⱼ exp[−½(u²/sₓ² + v²/sᵧ²)]
I(p) = clip(round(Σⱼ gⱼ(p)), 0, 255)

u、v 为旋转到高斯局部坐标后的像素位置。损失 L 是 I 与目标的全图 MSE；取整和截断在求和以后进行，不能先截断 S 再做增量更新。

真正要消掉的浪费

S′(p) = S(p) − gₒₗd(p) + gₙₑw(p)

原版每次只改一个参数，却重算所有像素上的所有高斯，重复三角函数并 JSON 深拷贝整个数组。缓存总和与单颗贡献，候选只算一颗：每步从 O(PN) 降至 O(P)，贡献缓存占 O(PN) 内存。

01 / PROPOSE

选择高斯与参数

均匀扰动并保留原 clamp。位置步长 2，尺度 1，角度 0.1，幅度 10。

02 / EVALUATE

只求新增贡献

sin/cos 每颗预计算；复用候选缓冲，仍评价全部像素，不截断尾部。

03 / ACCEPT

按原规则接受

min(1, exp(−ΔL/T))。损失是取整后图像的 MSE，SSE 用整数累加。

04 / COMMIT

接受后更新缓存

CPU 交换数组；GPU 在 block 内统一决策、同步提交，再开始下一步。

边界说明：clamp 提案在参数边界通常不对称，原代码没有 Hastings 修正，因此这里把它视为随机优化器，不保证严格分布采样。增量式是实数代数等价；浮点累积在半整数取整边界可能改变轨迹，一致性结论只覆盖已测用例。

04 / GPU DESIGN & UTILIZATION

让状态和迭代留在显存里。

本报告下方旧试跑仍为 JS CPU；独立 WebGPU / FP16 实验室已实现并测试。此节保留最初常驻 MCMC 内核设计。

已实现的并行布局

GPU grid: 32 independent chains
  each block: 256 threads
    thread 0    → proposal + acceptance decision
    all threads → pixels + integer SSE reduction
    barrier     → commit before next proposal

Parameters / contributions / sum / RNG stay on GPU.
Host launches 256-step chunks; no per-step readback.

一条链仍严格顺序执行。不能从同一旧状态提出多个重叠候选后全部接受。工作区约 C × P × (N+2) × dtype 字节，启动限制不超过当时空闲显存的一半。

MFU：统计口径与实测状态

最终渲染 + Adam 梯度两内核采样的 FP32 指令算术利用率约 14.97%。不是模型训练定义的 MFU，也不是整个程序平均。

  • renderSparse：SM throughput 73.23%，occupancy 83.97%。
  • refineAdam：SM throughput 66.33%，occupancy 83.07%。
  • 算术利用率使用实际 FADD + FMUL + 2×FFMA，按两内核时间和实测 SM 时钟加权；不含整数 / SFU / FP64，也不含 memset、MCMC、CPU、传输和空隙。

先前全图 MCMC 样本为3.85%，SM throughput 9.48%、occupancy 24.98%。新优化器增加跨高斯并行度。两组是不同阶段的内核样本，不能当作同一工作量的整体MFU对比。原始数据见 ncu_final.csv。

nvidia-smi 的 GPU Util 是采样期内的忙碌比例，不是峰值 FLOPS 利用率，还包含其他进程。这个内核含 exp、除法、整数 SSE、同步，不能用“原始全量重算 FLOPs”作优化后的 MFU 分子；省掉的计算不算已执行 FLOPs。
