02 / ASIGHT + PYTORCH

目前的瓶颈在哪里

U-Net：先解决启动，再看布局

每步约 2,730 个 kernel。Graph 保留这些 kernel，减少逐个提交产生的间隙。ASight 中卷积约 10.5 ms、Copy / cast 约 9.0 ms；PyTorch 同 trace 关联表明复制同时包含 dtype 与 NCHW / NHWC 布局转换。

下一步最值得试的是保持 channels-last 的 GroupNorm / SiLU 路径，减少来回转换。当前没有实现它，也不把全部 Copy / cast 都归因于 GroupNorm。

JiT：局部融合优先

保留厂商 GEMM 和 Flash attention。只把残差流中 25 个无仿射 RMSNorm 的前向、反向替换为 Triton：FP32 归约、原 epsilon 与输入输出 dtype 不变；带权重的 Q / K norm 保持原样。

下一步可比较 RMSNorm + modulation、SwiGLU 融合；改变累加顺序或中间 FP16 舍入时必须重新核对梯度与训练轨迹。

04 / TOOL RELIABILITY

保留失败，界定工具能说明什么

首轮 JiT ASight 子进程退出 SIGSEGV，没有生成 trace；随后一个 Triton 测速进程也退出 SIGSEGV，当时另一任务在运行 ASight。原因尚未证实。失败日志保留，JiT 全矩阵在其他 profiler 结束后重新执行；正式统计使用独立复测目录，不混入失败轮次。

05 / REUSABLE TRAINING PATH

加速实现已用于正式续训

src/train_finetune_fast.py 默认启用 Graph，继续保留两份 EMA、原学习率与断点格式。复制 checkpoint 和 training.json 到一个新输出目录，然后在已分配 PPU 的作业内运行；不要覆盖对照目录。

/usr/local/bin/python3 src/train_finetune_fast.py \
  --variant unet --batch 32 --resume \
  --finetune-lr 5e-5 --steps 80000 \
  --out results/YOUR_NEW_RUN

两条 U-Net 分支已用 Graph 从 60k 续到 80k，各 1 PPU；70k、80k 双 EMA 评估均完成。后续四组 16 PPU 训练也已完成，累计各 512 万张次，见主报告最终对照。可加 --acceleration eager 使用原训练路径。Graph 捕获有一次性成本，并保留私有内存池；固定 shape 的长训练更适合它。JiT 的 Graph + Triton 路径已用于两组 16 PPU 续训并完成质量评估；训练量和 batch 与历史基线不同，不能把质量变化单独归因于 Triton。
