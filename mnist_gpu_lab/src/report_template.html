速度与准确率一起看

实现训练 + 测试含准备阶段第 5 轮测试准确率PyTorch 峰值 allocated

主对照使用相同初始 seed、相同每轮样本顺序与相同超参；FP32 Graph 单步与 fused eager 已验证。不同内核、Adam 实现和非确定性卷积会累积浮点差异；准确率范围按实际重复运行给出。

每次只加一项：batch=128 微基准

每模式先 warmup 20 步，再测 5 组 × 80 步；每组起止同步 CUDA，含采样、前后向、Adam 和指标累积。使用固定 batch，衡量执行吞吐，不代表收敛时间；CPU 为 4 线程。

为什么不直接默认 FP16？

这只有 2.5 万参数。减少 Python 和驱动逐算子提交的开销，比盲目增加复杂优化更有效。

—AMP 每步中位数
—AMP 图捕获准备

AMP 使用 channels_last、FP16 autocast、FP32 参数和固定 loss scale 128，并按轮检查非有限值。小尾 batch 的首次 cuDNN 搜索仍计入训练时间。当前短任务 FP32 更合适；长训练才可能摊薄这些开销。

channels_last 单独打开也未稳定加速，未设为默认。没有更改 batch size 来夸大“同算法”收益。

学习目标没有改变

卷积使用 same padding，池化为 2×2 / stride 2 / valid。优化版直接输出 logits，再用稳定的交叉熵实现 Softmax + NLL；整数标签代替 one-hot，目标等价。全连接前显式保留原来的 NHWC 展平顺序。

训练步骤变成可回放的 GPU 图

索引取样 → Conv / Pool → CE → backward → Adam → 累积指标 一次捕获，多次回放。每轮只上传一次洗牌索引；完整图片与标签留在显存。末尾 96 张用 eager 路径处理，不丢样本。

初始化采用 Glorot uniform / zero bias；PyTorch Adam 设置 ε=1e−7。TF.js 与 PyTorch 的随机数生成、epsilon 放置和优化器数值实现不保证逐步一致；架构与导出权重的前向一致性单独验证。

A / DATA LAYOUT

PNG 是存储格式

6860² → 245×245 tiles，保留前 60,000 张，截掉 25 个空位。测试图 2800² → 100×100 tiles。使用 reshape + transpose 恢复样本，全部保持 uint8 原像素。

B / RESIDENCY

一次解码，一次上传

缓存为无压缩 NPZ；训练时归一化，GPU 数据常驻。完整输入的 FP32 像素约 209.4 MiB。没有逐 batch 的 DataLoader / Python 样本循环和 H2D 图片传输。

C / GRAPH LIFETIME

保持地址，恢复状态

图捕获前预热后，原位恢复模型与 Adam 状态。梯度缓冲区保持固定地址，使小尾 batch 与后续图回放可以安全衔接。结果验证包含这条路径。

    如何解读这次实验
    这台 GPU 同时运行桌面、游戏进程及其他计算，未占用独占设备，也未终止用户进程。耗时会随负载改变。报告展示重复运行范围，10 轮补充实验也完整保留；它不能用于推导稳定的独占 GPU 吞吐。
    “训练 + 测试”包含每轮洗牌、全部 batch、每轮全测试集评估；“含准备阶段”额外包含 NPZ 读取、设备上传、模型 / 优化器创建、图捕获、环境信息与日志。两者均不含 Python 启动 / import、首次下载与 PNG→NPZ 转换、最终导出及复读验证。GPU 计时边界均同步设备。
    CPU 使用 4 线程；GPU 对照模型和批量相同。浏览器是 M5 的硬件 WebGL（ANGLE Metal），非软件 SwiftShader；其首轮 shader 编译与后续热运行分开列出。测试集每轮用于展示，不能作为独立调参验证集。
